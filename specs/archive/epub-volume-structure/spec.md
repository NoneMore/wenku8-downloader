# EPUB 卷结构保留

本文规定本次修复的目标行为，尚未代表代码已经实现。后续需求调整在本文中直接更新，并同步受影响的边界和验收条件。

## 问题与已确定的选择

当前书稿保留 `Book.volumes[].chapters[]`，`nav.xhtml` 也按卷嵌套章节，但卷名只是无链接的文本。EPUB 正文仅依次输出章节，没有卷标题页；连续阅读时无法通过卷扉页识别卷间过渡。

目前没有具体阅读器的复现证据，不能断言无链接卷节点一定导致阅读器将目录压平。本次修复以产物中的卷章层级、可跳转卷节点和正文卷边界为验收对象。

用户已确定采用**独立卷扉页**：目录卷名跳转到扉页，连续阅读在进入每卷章节前经过该卷扉页。

## 目标行为

### 卷扉页与阅读顺序

- 对输入书稿中的每一卷生成一份独立 XHTML 卷扉页，清楚显示该卷原有标题。
- 卷扉页进入正常连续阅读顺序，并紧邻该卷第一章之前；前一卷结束后先进入下一卷扉页，再进入下一卷章节。
- 卷和章节的排列以输入数组顺序为准，不按名称、ID 或 `index` 字段重新排序。
- 卷标题和章节标题保留原文，正确转义 XML 特殊字符。重名卷、不同卷中的重名章节仍是独立条目，不能合并或跳转到其他卷章。
- 章节正文、插图及其先后顺序保持原有内容，不因增加扉页而遗漏、重复或移动到其他卷。

### 目录与包内引用

- EPUB 3 导航目录继续表达“卷 → 该卷章节”的两级层次。卷节点是指向本卷扉页的可用链接，各章节点仍直接链接到对应章节。
- 每份卷扉页和章节文档均有唯一、有效的资源登记，阅读顺序中的引用均可解析到对应资源。
- 目录目标必须存在于最终 EPUB 中；新增卷扉页不得与章节或其他资源发生文件名、资源 ID 冲突。
- EPUB 的 `spine` 仍表达线性阅读顺序；本次要求通过插入卷扉页保留正文卷边界，不要求将 `spine` 改为嵌套结构。

### 边界场景

- 单卷书籍同样生成卷扉页，并保留卷节点及其章节层级。
- 源站没有卷标题、解析器以“正文”表示的默认卷，按输入中的普通卷处理：生成“正文”扉页及对应目录节点，不推测或编造卷名。
- 若书稿包含空卷和非空卷，空卷仍保留原有位置、标题、可跳转扉页和目录节点，但不输出空的章节子列表；它的扉页后直接进入下一卷扉页或结束。
- 全书无卷、全书无章节等输入仍遵循现有完整性校验及显式放宽选项的行为，不能通过生成扉页绕过原有校验。
- 有无封面均适用；封面目录条目、封面内容及其既有阅读顺序属性保持现有行为。

## 范围与兼容性

- 范围为 EPUB 渲染、导航、资源登记、阅读顺序及必要回归测试。本规格阶段不修改实现。
- 继续输出 EPUB 3，保留现有图片完整性检查、包内图片引用和 ZIP 首个 `mimetype` 条目不压缩的约束。
- 兼容现有 `Book` 数据和 Manifest v1；使用已有完整书稿及资源调用构建器即可得到新卷结构，不要求修改缓存或重新抓取内容。
- 不新增 CLI 选项，不改变章节下载、认证、重试和缺图放宽语义。
- 不拆分为每卷一本 EPUB，不为卷新增封面图片，不增加每卷独立章节目录，不修改源站解析规则，不新增 EPUB 2 / NCX 支持。
- 不自动修改已经生成的 EPUB。新行为适用于修复后的构建输出。
- 不承诺所有阅读器以相同样式显示或展开目录；验收保证 EPUB 中提供正确的嵌套目录、可用链接和卷扉页。

## 验收条件

1. **多卷连续阅读**：以至少两卷、每卷至少两章的离线书稿构建，按 `spine` 解析资源后，正文顺序严格为“第一卷扉页 → 第一卷各章 → 第二卷扉页 → 第二卷各章”；每卷扉页恰好出现一次，全部章节恰好出现一次。
2. **目录层级及跳转**：解析导航文档，确认每卷是顶层卷节点，其章节只位于该节点的子列表；卷链接指向正确扉页，章节链接指向正确正文。所有目标在最终包中存在。
3. **标题与身份**：使用包含 `&`、`<` 等字符的标题，以及重名卷、跨卷重名章节，确认 XML 可解析、显示文本与输入一致，各条目链接准确且资源身份互不冲突。
4. **边界场景**：覆盖单卷、默认“正文”卷、空卷夹在非空卷之间及末尾空卷，验证上述扉页、目录、阅读顺序规则；保留对无卷、无章节输入的现有校验行为。
5. **内容与兼容性**：使用现有数据结构和本地资源构建，无需新增持久化字段；带插图章节的内容及图片引用保持正确，有封面和无封面均可构建，缺图校验及显式放宽行为不发生变化。
6. **EPUB 完整性**：所有新增资源均登记且引用有效，ZIP 首个条目仍为未压缩的 `mimetype`；新增多卷构建样例纳入现有 `CI_EPUBCHECK=1` 测试路径并通过 EPUBCheck。
7. **工程验证与文档**：实现完成后运行 `pnpm check`，记录 EPUBCheck 的实际执行结果或未执行原因；同步架构概览中 EPUB 的高层行为说明。

## 未决事项
