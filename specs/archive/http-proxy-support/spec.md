# HTTP 代理与环境变量继承

本规格保留 PR #4 的需求与验收约定。2026-10-26 根据用户审阅收敛范围：取消三种传输在全部路由、绕过和诊断细节上的强一致承诺，删除自维护浏览器转发器，使用成熟库和原生代理入口。此调整替代先前过细的跨工具约定，不改变本次代理功能的核心目标。

## 必需行为

- 登录、搜索与下载支持无需认证的 HTTP 代理，HTTPS 连接保持正常证书验证。
- 全局 `--proxy http://host:port` 显式指定代理，覆盖环境代理与绕过设置；`--no-proxy` 强制直连。两个选项互斥，适用于普通子命令和交互模式。
- 默认合理继承 `http_proxy`、`https_proxy`、`all_proxy`、`no_proxy` 及相应大写名称。细节沿用成熟解析库或底层工具，不要求三套传输的全部边缘行为相同。
- `NO_PROXY` 中不受支持或与当前目标无关的条目不阻断普通请求；未配置代理时，不校验绕过列表。有效 IP CIDR 排除项不得因 Node 解析库不支持而将匹配的 IP 目标送往代理；不额外通过 DNS 将域名转换为 IP 来匹配。
- 代理连接或认证失败报告错误，不暗中直连。配置错误、确定的 407 等不可恢复错误不能被误当成缺图或章节不可用；不额外重放账号登录 POST。
- 参数和诊断不回显含认证信息的代理 URL。代理不持久化，不改变会话、Manifest、缓存和断点恢复格式。
- 未配置代理时保留原有普通 fetch 路径，不新增调用方需要管理的连接生命周期。

## 实现边界

- Node 使用 `proxy-from-env` 选择环境代理；代理请求创建 undici ProxyAgent，显式强制直连使用直连 Agent，均在响应或失败后由 HTTP 层自行释放，不缓存 dispatcher。未配置代理时不设置 dispatcher。使用 Node BlockList 补足 IP 字面量的有效 CIDR 排除，不维护完整的自定义绕过语法。
- curl 自动模式保留原生环境变量、绕过及用户配置；显式代理只覆盖代理和绕过选项，强制直连禁用代理。不清空子进程环境，不全面禁用 curl 配置。curl 对大写 `HTTP_PROXY` 等变量的原生限制保留。
- 浏览器使用 Playwright 原生 `proxy`。自动模式按 HTTPS 登录页选定一次代理或直连；若选用代理，将 `NO_PROXY` 交由 Chromium 原生处理。后续页面及子资源使用该浏览器配置，不实现逐请求、按协议切换代理的转发服务。显式代理忽略绕过列表，显式直连使用原生 direct 配置。
- HTTP 层用通用的 `NonRetryableHttpError` 表达不可恢复失败，上层沿现有终止路径传播；不递归匹配底层异常文本来猜测 407，不维护代理专用业务错误类别。
- 不增加代理池、PAC、系统代理发现、持久化代理设置、代理认证、HTTPS 代理服务器或 SOCKS 的产品支持承诺。

## 验收

1. 轻量测试覆盖环境代理、显式覆盖、常见绕过、无代理时的普通 fetch，以及无关 `NO_PROXY` 和 IP CIDR 排除的兼容性回归。
2. Node 与 curl 各验证一条实际 HTTP 代理链路和一条 HTTPS CONNECT 链路；HTTPS 成功须信任测试 CA，未信任时仍失败。
3. 代理不可连接或返回 407 时明确失败，目标没有收到直连请求；日志不泄露误传的代理凭证。
4. 实际浏览器通过原生代理登录，CLI 能以所得 Cookie 验证账号；另保留一条实际 CLI 代理请求冒烟测试。
5. 使用既有下载器测试核实不可恢复错误不被章节回退或缺图容错吞掉；代理测试不重新建立整套下载、图片和恢复模拟站点。
6. 执行 `pnpm check`、定向格式检查及安装包预检，更新 README 和架构说明，推送到同一 PR。
