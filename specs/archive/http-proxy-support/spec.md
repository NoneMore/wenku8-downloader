# HTTP 代理与环境变量继承

本文保留本次功能的需求与验收条件。实现与验证结果见文末；后续需求使用新的 Change，不将未覆盖环境视为已经验证。

归档原因：约定范围已实施并通过本地验收，代理策略、三条传输路径、CLI、回归测试与使用文档已完成；远程检查由 [PR #4](https://github.com/NoneMore/wenku8-downloader/pull/4) 继续验证。

## 目标与已确定的选择

让用户在需要代理的网络环境中完成登录、浏览器验证、搜索和下载。已有代理环境变量时，无需为 wenku8 重复配置；也可以针对一次运行强制指定代理或直连。

用户已确定：

- 首版支持无需认证的 HTTP 代理，例如 `http://127.0.0.1:7890`，可用于访问 HTTP 和 HTTPS 目标。
- 自动读取代理环境变量，提供 `--proxy <url>` 和 `--no-proxy` 显式覆盖。
- `--no-proxy` 强制全部直连；`--proxy` 强制全部使用指定代理，忽略环境变量及 `NO_PROXY`。
- 自动模式按目标协议读取 `HTTP_PROXY` / `HTTPS_PROXY`，以 `ALL_PROXY` 兜底，并遵守 `NO_PROXY`。
- 环境变量同时支持大小写名称；同名的两种大小写同时存在时，非空小写值优先。
- `NO_PROXY` 首版支持逗号列表、域名及子域名、精确 IP 和 `*`；暂不支持端口限定与 CIDR 网段。

## 变更前实现与影响范围

- [`src/http/client.ts`](../../../src/http/client.ts) 集中处理 Node `fetch`、curl、重定向、限速、超时与重试，但没有统一的代理选项或环境变量解析。curl 子进程继承进程环境，程序未显式统一其代理行为。
- [`src/auth/login.ts`](../../../src/auth/login.ts) 直接登录使用 Node；[`src/auth/browser.ts`](../../../src/auth/browser.ts) 必要时启动 Playwright 浏览器，并分别使用 curl、Node 验证会话交接。当前没有向浏览器传递统一代理策略。
- [`src/cli.ts`](../../../src/cli.ts) 创建业务客户端并复用会话保存的传输类型。新增代理行为必须覆盖认证与业务请求，不能只修改下载命令。
- [`src/site/client.ts`](../../../src/site/client.ts) 的 `Wenku8Client` 接收 `HttpClientOptions`。底层客户端应统一执行代理策略，避免库调用与 CLI 在相同配置下使用不同的出口规则；具体新增类型和字段命名由实现确定。

## 预期行为

### 配置入口与覆盖顺序

| 输入                       | 路由行为                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------- |
| `--no-proxy`               | 本次运行全部直连，不使用代理环境变量、绕过列表或系统代理                                        |
| `--proxy http://host:port` | 本次运行全部使用指定代理，忽略代理环境变量和绕过列表                                            |
| 未传上述参数               | 自动模式：先检查目标是否命中 `NO_PROXY`，再选择对应协议的代理或 `ALL_PROXY`，没有可用配置则直连 |

1. 两个选项适用于 `login`、`search`、`toplist`、`sugoi`、`info`、`download`、`resume` 及无子命令的交互模式；从查询结果继续下载时沿用同一策略。
2. 作为全局选项，在子命令前后均可使用；例如 `wenku8 --proxy http://127.0.0.1:7890 info 1973` 与 `wenku8 info 1973 --proxy http://127.0.0.1:7890` 等效。
3. 同时提供 `--proxy` 和 `--no-proxy` 属于冲突，必须在发送请求前报错，不依赖参数先后顺序选择其中一个。
4. 显式配置不受无效或不受支持的环境变量影响。`--no-proxy` 也必须阻止 curl 或浏览器自行读取其他代理来源。
5. 代理配置只影响本次运行，不保存到账号会话、工作区 Manifest 或新增持久化配置中。后续进程重新读取自己的参数与环境。
6. 库调用可表达自动、指定代理、强制直连三种相同模式；不要求调用方修改进程全局环境或全局网络配置。

### 自动继承环境变量

| 目标 / 用途 | 首选变量                     | 备用变量                 |
| ----------- | ---------------------------- | ------------------------ |
| HTTP 目标   | `http_proxy`、`HTTP_PROXY`   | `all_proxy`、`ALL_PROXY` |
| HTTPS 目标  | `https_proxy`、`HTTPS_PROXY` | `all_proxy`、`ALL_PROXY` |
| 绕过列表    | `no_proxy`、`NO_PROXY`       | 无                       |

- 每组变量先去除值首尾空白；空值按未设置处理。大小写名称可同时存在的平台上，非空小写值优先；Windows 按其环境变量不区分大小写的实际行为处理，不要求制造两份独立变量。
- HTTPS 目标不以 `HTTP_PROXY` 代替缺失的 `HTTPS_PROXY`；只有 `ALL_PROXY` 可以作为跨协议的兜底。变量名中的 HTTPS 表示目标协议，其值仍须为本版支持的 `http://` 代理地址。
- 没有代理配置时维持直接访问。系统代理设置、浏览器系统配置或 curl 用户配置不得另行改变已经解析出的路由。
- 每次重定向按新目标的协议与主机重新判定路由；不得把初始目标的代理选择或绕过结论无条件沿用到其他目标。
- Node、curl 和浏览器使用同一套解析结果。不能因为原生库对变量大小写、空值或默认绕过规则的处理不同而改变行为。
- 仅检查当前模式和实际目标会使用的配置。未选中的代理变量不应阻止有效配置生效；纯离线命令和帮助、版本输出不因代理环境变量无效而失败。

### `NO_PROXY` 匹配

仅自动模式应用下列规则：

- 列表以逗号分隔，忽略条目首尾空白与空条目；空列表不绕过任何目标。
- 独立条目 `*` 表示全部直连。不支持将星号嵌入域名的通配模式。
- 域名匹配不区分大小写，按完整域名标签匹配本域及子域；前导点与无前导点等效。例如 `example.test` 和 `.example.test` 均匹配 `example.test`、`a.example.test`，不匹配 `notexample.test` 或 `example.test.other`。
- 域名条目不限定端口，同一主机的不同端口均适用。
- IPv4、IPv6 条目只匹配 URL 中的对应 IP 地址；IPv6 条目使用无方括号形式。IP 比较按地址含义进行，不按文本前缀匹配。
- 不通过 DNS 解析将域名与 IP 条目相互匹配。
- 本版不支持的端口限定、CIDR、嵌入星号等条目应明确报告不受支持，不得交给某条传输自行解释，或静默解释为另一种规则。自动模式中需使用绕过列表时，在发请求前报告此类配置错误。
- 不额外隐式绕过 localhost 或回环地址；需要绕过时显式列入 `NO_PROXY`。强制代理模式同样不得因浏览器默认的本地地址绕过而悄悄直连。

### 代理协议与错误

1. 支持 `http://` 代理地址，具备有效主机及可选端口；省略端口使用 HTTP 默认端口。代理地址表示服务器端点，不接受业务路径、查询或片段。
2. 通过 HTTP 代理请求 HTTP 资源，并通过 CONNECT 隧道请求 HTTPS 资源。访问 HTTPS 时保留正常 TLS 证书验证，不以关闭验证使代理可用。
3. `https://`、SOCKS 等代理协议以及带用户名、密码的代理 URL 不属于首版支持范围。实际选中的配置包含这些内容时，在发请求前明确报错，不尝试认证或自动换用另一条传输绕过限制。
4. 代理连接失败、隧道失败等网络问题可沿用现有适用的超时、重试和取消机制，但不能自动改为直连或改用其他代理地址。
5. 代理返回 HTTP 407 时，明确提示需要代理认证、当前版本不支持；不将其当作站点登录失效，不自动重放登录 POST，也不为解决代理认证打开站点登录浏览器。代理配置错误与 407 沿下载包、章节和图片路径直接传播，不因候选 URL 回退、章节整轮重试或 `--allow-missing-images` 被转换为其他结果。
6. 配置错误提示指出参数或变量名称及错误类别，不回显完整输入值。即使用户误传含认证信息的代理地址，也不得把用户名、密码写入终端错误、重试日志或浏览器诊断。

### 登录、下载与兼容性

- 直接登录、浏览器人工验证、浏览器后的 Node/curl 会话可用性检查，以及后续业务请求，均遵循当前模式对各目标的路由判定。
- 浏览器页面、表单提交和验证所需的子资源也必须执行该策略，不能只给 CLI HTTP 请求设置代理。HTTP 与 HTTPS 环境代理不同、仅配置其中一种时，仍需保持逐目标选择的一致性。
- 会话文件记录的 `transport` 继续决定 Node/curl 传输，不覆盖本次代理设置。切换传输或尝试另一种交接候选时不得更换路由策略。
- 保留现有登录成功判据、Cookie 作用域、认证重定向约束、禁止自动重放登录 POST、限速与 429 冷却规则。
- 更改出口可能使站点要求重新登录或验证；不承诺代理能避免站点验证。交接失败仍按现有规则报告失败，不保存为可用新会话。
- 章节、封面、插图与打包资源均适用代理；下载失败时保留现有进度，不能因代理问题绕过章节和图片完整性检查。
- 继续支持 Node.js `>=22.13` 及现有 Windows、macOS、Linux 使用方式；不能仅依赖更高版本运行时的默认代理行为，也不使原本只需 Node 的直接登录额外依赖 curl。
- 保持 Manifest v1、会话格式、缓存与断点恢复兼容。离线状态检查、插图检查、EPUB 构建与校验不增加联网要求。

## 非目标

本次不支持 HTTPS 代理服务器、SOCKS、代理认证、PAC、自动发现操作系统代理、代理池或失败时轮换出口。不新增持久化代理配置、交互式代理设置菜单、代理测速或网络诊断功能；不改变站点认证与防护策略。

## 验收条件

使用可控的本地 HTTP / HTTPS 目标和代理记录实际连接，不能仅以选项对象或模拟 `fetch` 调用证明请求经过代理。测试环境隔离宿主机代理配置，使用脱敏数据，不依赖真实账号。

| 场景                                                | 可观察结果                                                             |
| --------------------------------------------------- | ---------------------------------------------------------------------- |
| 无参数、无代理环境变量                              | Node、curl、登录浏览器均直接请求目标，现有业务行为保持正常             |
| 自动模式 HTTP / HTTPS 分别配置                      | 各目标分别到达对应代理，HTTPS 经 CONNECT 且仍验证证书                  |
| 只有 `ALL_PROXY`，或协议变量与其同时存在            | 缺失协议代理时使用兜底；存在协议代理时优先使用协议代理                 |
| 仅配置 `HTTP_PROXY` 后访问 HTTPS                    | 不误用 HTTP 目标的代理；无 `ALL_PROXY` 时直连                          |
| 大小写冲突、空值、首尾空白                          | 按本规格选出唯一有效值；Windows 行为与平台环境模型相符                 |
| 环境变量无效但指定有效 `--proxy` 或 `--no-proxy`    | 显式策略仍生效，不被无关环境配置阻断                                   |
| `--proxy` 与 `NO_PROXY=*` 同时存在                  | 全部目标仍经过指定代理，包括回环目标                                   |
| `--no-proxy` 与所有代理环境变量同时存在             | Node、curl、浏览器均直连，无代理连接记录                               |
| 两个显式选项同时提供，参数位于子命令前或后          | 冲突稳定报错；单独使用时两种位置等效，交互模式也支持                   |
| 绕过列表包含域名、前导点、相似域名、IP、空条目、`*` | 代理与直连连接记录符合匹配规则；域名与 IP 不经 DNS 相互匹配            |
| 绕过条目使用端口、CIDR 或嵌入星号                   | 自动模式明确报配置错误；显式模式忽略未使用的绕过列表                   |
| 重定向改变协议、主机或绕过匹配结果                  | 每跳到达正确代理或直连目标，原有 Cookie 及认证重定向约束仍成立         |
| Node 切换到 curl，或浏览器会话交接依次尝试两者      | 传输改变，代理策略保持一致；不会无提示地换出口                         |
| 浏览器登录页、表单与验证子资源                      | 实际连接均符合相同路由规则；不同协议代理、绕过与强制直连场景均覆盖     |
| 无效地址、不支持协议或 URL 中带代理凭证             | 首次相关请求前失败，错误不泄露输入中的秘密，目标和代理均未收到该请求   |
| 代理拒绝连接、CONNECT 失败或 HTTP 407               | 失败明确，无直连回退；407 不触发站点登录流程或认证 POST 重放           |
| 超时、取消及允许的重试                              | 使用原有控制机制，取消后释放代理连接及浏览器资源，不额外重放认证提交   |
| 通过代理获取详情、目录、章节、封面和插图            | 全部资源经过正确路由；中断恢复仍能复用已下载资源，完整性规则保持有效   |
| 旧会话和旧工作区；离线命令遇到无效代理环境          | 旧数据仍可读取；纯离线操作、帮助和版本输出照常可用                     |
| 检查日志、保存文件与进程启动参数                    | 不新增代理持久化；误传的代理认证信息未被复制进日志、会话或子进程命令行 |

实施后运行 `pnpm check`，增加与上述路由及失败行为对应的必要回归测试；浏览器验收包含真实浏览器网络连接，不以页面路由模拟代替代理连通性验证。记录实际验证的平台与浏览器，明确尚未覆盖的组合。

README 和 CLI 帮助需说明覆盖顺序、支持的变量、仅 HTTP 无认证的边界，以及 `NO_PROXY` 的匹配范围。至少提供 PowerShell 和 POSIX shell 的环境变量示例，并说明 `HTTPS_PROXY=http://127.0.0.1:7890` 是为 HTTPS 目标选择 HTTP 代理。实现完成后同步架构概览中的统一网络策略。

## 实施选择与未决事项

没有尚待用户决定的产品范围。实现使用统一 `ProxyPolicy`，Node 使用 undici 7（依赖要求 Node.js >=20.18.1，与项目最低版本兼容），curl 显式传递解析结果并禁用用户代理配置；库调用通过 `proxy?: string | false` 表达三种模式。

浏览器使用临时本地 HTTP 转发服务，执行相同的逐目标策略，CONNECT 保持字节隧道而不终止 TLS。真实 Edge 网络测试已覆盖不同协议使用不同代理、部分协议直连、绕过和强制直连；登录完成、取消或失败时释放浏览器和转发连接。代理错误按实际页面请求的目标归属，避免浏览器后台流量干扰登录结果。

参考资料只用于核实底层能力，不覆盖本文已确定的产品规则：

- [curl 环境变量文档](https://curl.se/docs/manpage.html#ENVIRONMENT) 记载其变量与绕过行为；其中 `HTTP_PROXY` 的大小写例外和显式代理仍受 `NO_PROXY` 影响等规则与本次约定不同，需要显式适配。
- [Playwright HTTP 代理文档](https://playwright.dev/docs/network#http-proxy) 提供浏览器 / 上下文代理及绕过入口，但不足以单独证明本规格所有路由组合已经可用。
