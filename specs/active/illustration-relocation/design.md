# 基于明确关联的插图重定位设计

本文记录当前 active Change 的实施设计。需求与验收见 [spec.md](spec.md)。

## 实施价值与范围决策

值得实现一个有边界的能力：恢复正文已经给出的图片 URL，并执行经过核实的本地定位映射。这样既能改善实际存在的解析遗漏，也能让不同书籍使用同一套重排和校验机制。

当前证据不足以支持“任意小说自动恢复原书插图排版”。只有编号而图片侧没有对应标签时，位置信息并不完整；将编号解释为画廊序号，会生成图片齐全但位置错误的 EPUB，现有缺图校验也发现不了这种错误。

本 Change 已进入实施，范围在一个 PR 内闭合。默认输出保持现状；新能力显式启用。对 2883，没有核实映射时仍不移动编号插图，不能把提供检查能力描述为已经解决了该书的重定位。

规格审阅后补齐三个边界：旧解析器已拆散的 URL 标记不在首版恢复承诺内；符号标记采用固定的接受集合；离线检查采用版本化报告和明确的部分完成语义。这样保留已有源坐标与缓存兼容性，不把缓存修复或模糊识别引入本 Change。

## 用户入口

新增以下明确入口，首版只在 `download` 命令和对应库 API 暴露，不给交互菜单增加编辑器：

```text
wenku8 illustrations <book> --work-dir <directory> --json
wenku8 download <book> --relocate-illustrations
wenku8 download <book> --illustration-map <file>
```

- `illustrations` 是离线检查命令，输出本地源快照中的标记、已有图片块、章节地址、块坐标、章节摘要和可用图片文件摘要。没有 `--json` 时显示摘要，带此选项时输出规格规定的 JSON 报告 v1。用户核对本地图片或自己的排版参考后填写映射；报告不自动选图。
- `--relocate-illustrations` 启用明确 URL 引用恢复，并汇总仍未解析的符号标记。
- `--illustration-map` 加载本地映射，同时启用上述恢复能力。命令名称不承诺自动配对编号。
- 库 API 对应 `DownloadOptions.relocateIllustrations?: boolean` 和 `illustrationMap?: IllustrationMap`；CLI 负责文件读取和结构校验，业务层接收数据对象。
- 所有选项缺省时维持原行为。显式 URL 恢复可能新增图片下载，进而触发既有缺图检查，因此不默认启用。

检查报告使用源章节缓存和当前可核验的本地资源。它不读取已经重排的 `book.json` 章节作为输入。`book.json` 中的资源路径可以辅助查找文件，但摘要必须从实际文件重新计算。缺少章节或资源时列明缺项；没有图片文件摘要的候选不能成为可执行映射。可信 Manifest、已完成的目录记录及目录原文是必要输入；用目录记录中的 URL 解析相对链接，按目录读取已完成章节，不能把目录外缓存混入报告。章节缓存原文和 `book.json` 均可缺省，读取图片时沿用工作区内路径约束。

报告以 `complete` / `partial` / `error` 区分检查完整、部分可检查及无法建立可信输入，退出码分别为 `0` / `2` / `1`。部分报告保留有效章节结果；致命输入错误不导出候选。完整检查允许有未映射标记，不承诺排版恢复。JSON 字段、原因码、排序、资源可用性及缺缓存矩阵以 [spec.md 的离线检查契约](spec.md#离线检查契约) 为准，不另维护第二套报告 schema。

检查不调用会创建目录和保存 Manifest 的 `BookWorkspace.open()`，而使用内部只读加载逻辑；不加载登录态。报告只输出受支持的完整标记、位置及资源元数据，不将普通小说段落、URL 碎片或凭证写入控制台。`--json` 的 stdout 仅包含一个报告对象，包括部分及错误结果。

## 职责与数据流

首版不引入通用书源插件框架或新的持久化 `ContentBlock` 类型。将复杂度集中在两个有实际职责的模块中：

- `src/site/illustrations.ts`：识别 Wenku8 遗留标记，在源章节副本中恢复明确引用，保留无法解析的原标签。它同时服务在线解析结果和缓存章节。
- `src/domain/illustration-layout.ts`：校验本地映射，规划并执行确定的块替换和移除，返回派生书稿与诊断。它处理已有章节和资源身份，不了解站点 HTML，也不发起网络请求。

```text
源目录与源章节缓存
  → 识别标记，校验映射坐标，派生明确 URL 的图片块
  → ImageStore 获取资源并绑定 assetId
  → 核实映射所需资源摘要，一次性应用全部移动
  → 写入派生 book.json 与本次布局报告
  → 既有完整性检查、XHTML 渲染和 EPUB 打包
```

`Downloader` 负责上述编排，现有 HTTP、图片缓存和 EPUB 模块继续承担各自职责。图片资源集合包含所有源图片和恢复出的 URL；不因图片将被移走就跳过获取或校验。EPUB 层只接收普通 `ImageBlock`，不识别 `插图008` 等站点语法。

恢复和映射先建立针对源坐标的操作集合，再从源书稿派生结果。首版只替换完整的标记段落，替换为一个图片块，不拆分正文段落；移动结束前不删除块，避免前一次编辑改变后续下标。

## 标记与图片身份

### 明确 URL

自动恢复仅接受整个普通段落由受支持图片标记组成的情况：大小写不敏感的 `[IMG]URL[/IMG]`，以及已观察到的 `IMG]URL[/IMG]`。两者均须包含单个完整、可解析的 HTTP 或 HTTPS 图片 URL；首版支持路径后缀为 JPEG、PNG、GIF、WebP 或 AVIF 的地址，保留查询参数和完整地址。

只裁剪段落外侧空白用于识别，URL 本身不允许字面空白，路径扩展名匹配不区分大小写。识别后直接采用原 URL 字符串，保留查询、片段和转义，不采用 `URL` 对象重新序列化的值。确切接受规则见规格。

普通网页链接、正文中的 URL、混有叙述的段落及格式不完整的其他变体保持原文。URL 不存在或响应不能解码为图片时，使用现有图片获取与完整性检查处理，不能以文字标记已被识别为由宣告恢复成功。

恢复 URL 引用只在原位置产生图片引用，不自动删除图库中相同 URL 的块。图库是否保留属于排版选择，资源 URL 相同也不能证明两次展示属于重复内容。

现有下载包解析会把部分标记拆散。例如合成的 `[IMG]https://example.test/picture.jpg?size=large[/IMG]` 会成为 `[IMG]` 段落、只含 `https://example.test/picture.jpg` 的图片块和 `?size=large[/IMG]` 段落。完整 URL 已不在单个源块内。首版不跨块重组，也不重解析缓存原文；无论新下载还是缓存复用，均保留这些源块，并按规格的碎片规则报告 `LEGACY_URL_FRAGMENT`，不计为恢复成功。缺少原文时也采用同一处理；原文存在不能触发隐式坐标重建。这是明确缩小的兼容承诺，未来修复下载包解析需另行评估源快照和映射失效。

### 符号标记

检测器仅接受 [spec.md 的符号标记识别契约](spec.md#符号标记识别契约) 列出的三类完整段落格式和字符范围，不把“文件名式”解释为任意文件名。识别时裁剪外侧空白，报告与映射仍使用未裁剪的源 `block.text`；编号保留为字符串，不丢前导零。原标签用于显示及精确校验；可额外解析数字、前缀和后缀作为内部信息，但这些字段不产生自动映射，也不擅自扩充 JSON v1 字段。

只支持完整段落，避免把小说中讨论插图的句子或后记中的普通文字改成图片。相同标签在同卷、不同章节乃至同章出现时均是独立位置。不按编号、出现顺序、图片数量或颜色推断对应关系，不维护书籍 ID 特例。

现有无地址 `ImageBlock` 仍由现有完整性规则处理；本 Change 的符号映射目标限于完整文字段落，不将旧占位块反推为原标记。

## 本地映射契约

映射文件独立于源缓存，版本号独立于 Manifest。首版使用以下概念结构，由严格 schema 校验：

```ts
type SourceCoordinate = {
  chapterUrl: string;
  chapterSha256: string;
  blockIndex: number;
};

type IllustrationMap = {
  version: 1;
  bookId: number;
  entries: Array<{
    target: SourceCoordinate & { marker: string };
    image: SourceCoordinate & {
      sourceUrl: string;
      assetSha256: string;
    };
    evidence: { reference: string; note?: string };
  }>;
};
```

- `blockIndex` 从零开始，始终指原始 `chapters/*.json` 的块位置。`chapterUrl` 必须准确匹配输入目录中的唯一章节；目录内部卷 ID 或卷下标不作为长期身份。
- 两处章节摘要均必填。摘要是源章节块的规范序列经 UTF-8 编码后的 SHA-256；序列用数组表达，文本为 `[type, text, level ?? null]`，图片为 `["image", sourceUrl, alt]`，分隔为 `["separator"]`，按块顺序 `JSON.stringify`。不包含 `assetId`，不依赖对象属性顺序。
- 目标块必须仍是识别出的普通文字标记，且文字与 `marker` 完全相同。来源必须仍是有地址的图片块，URL 与映射相同。两个章节必须属于同一卷；首版拒绝跨卷移动。
- `assetSha256` 对应 `ImageStore` 产出的规范化本地图片字节，不能仅相信 Manifest 中的旧值。图片重新规范化后字节变化也视为需要重新核验，不使用视觉相似度自动放宽。
- `evidence.reference` 记录用户核验所依据的出版物、文件或页面，`note` 可说明判断。记录的存在只是来源说明，不是程序已经认证其权威性；程序不访问这个地址。
- 映射中的 URL 只用于定位现有章节和来源图片块，不能指示额外下载陌生地址或读取任意本地文件。

首版选择“固定源快照加准确坐标”，而不是实现模糊锚点恢复。这样映射很容易因源正文改变而失效，但不会悄悄套用到另一版文本。检查命令负责生成摘要和坐标，用户无需手算。

[W3C TextQuoteSelector](https://www.w3.org/TR/annotation-model/#text-quote-selector)为未来使用文字与上下文定位提供了参考；它不能证明图片关联，故本 Change 不实现完整 Web Annotation 协议，也不在快照失配后自动搜索相似段落。

## 移动、冲突与失败语义

显式映射采用整体校验、整体应用：全部结构、章节、坐标和资源检查通过后，才生成重排书稿；任何一条失效都停止本次生成，不使用部分映射继续导出。

一条映射将目标文字块替换为来源图片块的副本，并将该来源块标记为移除。一个来源块可以由多条显式映射引用：在各目标展示同一资源，来源处只移除一次。一个目标只能被声明一次；即使重复声明内容相同也报错，避免掩盖合并错误。

没有选中的来源块保持原位；不能凭相同 URL 或相同图片摘要删掉其他出现位置。文字、未匹配彩页、人物介绍、预告及其相对次序均保留。只有原本不含文字、包含图片的来源章节，在所有图片被明确移走后仅剩分隔符时，才移除该空图片章及对应目录项。混有文字的章节继续保留。

| 情况                                   | 行为                                                       |
| -------------------------------------- | ---------------------------------------------------------- |
| 编号标记没有映射                       | 保留文字和图库位置，汇总为未解析，不新增无地址图片块       |
| URL 标记恢复后图片获取失败             | 按现有缺图规则阻止输出；显式 `allowMissingImages` 仍可放宽 |
| 已有无地址图片占位、已有图片缺失       | 继续遵循现有完整性检查                                     |
| 映射版本、书籍、章节或摘要不符         | 报告具体映射条目及原因，停止生成                           |
| 目标不唯一、重复目标、来源不匹配或跨卷 | 拒绝映射，停止生成                                         |
| 显式映射需要的资源缺失或字节摘要改变   | 停止生成；`allowMissingImages` 不放宽定位映射校验          |
| 用户中断或获取失败                     | 保留已完成的源缓存及图片缓存，不把部分重排写成成功结果     |

布局报告区分明确 URL 恢复数、映射应用数和未解析标记数，提供卷章、块位置、原标签与原因码。它不把未知位置等同于图片下载失败，也不以“全部图片已下载”宣称定位准确。

已检测到的 URL 碎片另列位置及 `LEGACY_URL_FRAGMENT`，不输出其文字，不计入恢复数。此限制不新增无地址图片块，也不使下载整体失败；保留的旧图片继续接受现有完整性检查。离线检查的 `partial` 是检查命令状态，不是下载失败条件。

报告与派生 `book.json` 在全部映射通过后由工作区写入。报告附带布局模式、源快照摘要及映射摘要；它是本次派生过程的记录，不是下一次生成的输入。中断后通过源缓存重新派生，不依靠两个文件原子提交维持正确性。

## 缓存与兼容性

- `raw/` 和 `chapters/` 是本功能的源输入，不覆盖为重排后的内容。源章节 JSON、`Book` 的块类型及 Manifest v1 不需要升级。
- 明确 URL 恢复在缓存加载后运行，旧缓存中仍完整保留的段落标记可直接获得新能力；已拆散的下载包标记只报告限制。首版不重解析原文、不批量迁移、不承诺还原已丢失的参数，也不通过整库重新下载掩盖该限制。
- `book.json` 仍是下载编排产生的最终派生书稿，包含本次启用的布局。直接调用 `EpubBuilder` 构建这个对象会沿用该布局；关闭布局重新生成时必须从源章节重建，不能把它反向还原。
- 新选项会影响派生输出，不改变下载资源是否完成。下一次运行读取本次指定的映射重新校验，不复用上次“定位已完成”状态。
- 同一源快照和映射产生相同内容排列；不要求 EPUB ZIP 字节完全相同，现有时间戳和随机标识可能变化。
- 已生成 EPUB 不自动修改。照片资源继续由 `ImageStore` 去重、校验和规范化；认证、限速、重试及章节失败终止语义保持既有职责。

## 备选方案与后续边界

| 方案                                 | 决策及理由                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------- |
| 所有编号直接匹配同卷第 N 张          | 不采用；章节编号重置、彩页及图片重排已有反例                               |
| 按指针数量和图片数量补齐、偏移匹配   | 不采用；数量吻合无法证明位置正确                                           |
| 仅修复明确 URL，完全不提供映射       | 价值明确但覆盖有限；本设计同时提供可验证的本地映射，承接真实的编号标记需求 |
| 自动抓取其他书源或出版物并迁移排版   | 推迟；尚未验证同译本识别、文本对齐和图片身份匹配的准确率与可获得性         |
