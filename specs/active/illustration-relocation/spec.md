# 基于明确关联的插图重定位

这是当前分支实施中的 active Change。设计依据、接口和取舍见 [design.md](design.md)。

## 目的

正文中的图片引用有时以文字标记保留，实际图片集中在另一章节。提供跨书籍可复用的恢复和重定位能力，让有明确关联或经过人工核实的图片出现在正文指定位置，同时保留没有充分依据的内容。

## 范围

- 显式启用后，恢复受支持的、独立段落中的图片 URL 标记。
- 识别正文插图标记并导出离线检查报告；标记只是定位线索，不等同于图片次序。
- 接受版本化的本地映射，将已有图片块移动到经过核实的正文标记处。
- 校验书籍、章节快照、目标标记、来源图片及文件摘要；显式映射有误时整体失败。
- 从源章节缓存派生输出，不覆盖原始 HTML 或源章节 JSON。

本 Change 不实现跨书源抓取、译本文本对齐、感知图像匹配、图形编辑器或共享映射服务，不内置单书对应表。

## 明确引用与旧缓存边界

恢复以加载后的源章节块为输入，不重新解析缓存原文。仅当一个 `paragraph` 块的文字经 ECMAScript `trim()` 后完整匹配 `[IMG]URL[/IMG]` 或 `IMG]URL[/IMG]` 时恢复；标签大小写不敏感。URL 必须是单个无字面空白、可解析的 HTTP/HTTPS 绝对地址，路径以 `.jpg`、`.jpeg`、`.png`、`.gif`、`.webp` 或 `.avif` 结尾，扩展名大小写不敏感。输出保留 URL 原字符串，包括查询参数、片段及转义，不通过 URL 序列化改写。

旧下载包解析可能已经把完整引用拆为多个块，并截掉图片 URL 的查询参数。首版不合并这些块、不补参数、不从原文重建；这类缓存不在完整引用恢复的兼容承诺内。具体诊断规则为：普通段落经 `trim()` 后等于 `[IMG]` 或 `IMG]`，或以 `[/IMG]` 结尾但不符合上述完整引用语法时，记为 `LEGACY_URL_FRAGMENT`，标签大小写不敏感。只报告块坐标和原因，不输出碎片正文，也不改变其图片或文字。

新下载与旧缓存使用相同的块级规则；若下载包解析路径已经拆散标记，新下载也受此限制。检查命令和下载布局报告必须揭示已检测到的限制，不能宣称这些引用已经恢复。用户若持有更完整的源输入，应重新检查并核验映射；本 Change 不提供缓存修复命令。

## 符号标记识别契约

仅检查 `paragraph` 块；用 `trim()` 后的文字进行下列完整匹配，保留未裁剪的 `block.text` 作为报告和映射中的 `marker`。映射校验与原块文字逐字相等，不做空白、繁简、大小写或 Unicode 规范化。编号是 ASCII 数字串，保留前导零。

| 类别         | 接受规则                                                                                                                 | 接受示例                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------- |
| 带括号编号   | `（插图` + 一个或多个数字 + `）`，或完全配对的半角括号形式；括号内无空白                                                 | `（插图008）`、`(插图008)`          |
| 章节前缀     | `第` + 一个或多个 `[0-9一二三四五六七八九十百千零〇两]` 字符 + `章` + 一个或多个半角或全角空格 + `插图` + 一个或多个数字 | `第一章 插图001`、`第12章　插图002` |
| 文件名式后缀 | `插图` + 一个或多个数字 + 一个或多个 `_` 加非空 ASCII 字母数字串的分组                                                   | `插图001_fmt`、`插图001_scan_fmt`   |

拒绝示例：`插图001`、`[插图001]`、`（插圖001）`、`（插图 001）`、`（插图001)`、`插图001_fmt.jpg`、`插图pic4_0124_fmt`、`见（插图001）`、`第一章插图001`、`第一章 插图001。`。相同文字若为 `heading` 或 `note` 也不识别。以上是首版刻意限定的支持集合，不声称覆盖全部录入格式；后续扩展需同步规格与样例。

## 离线检查契约

`wenku8 illustrations <book> [--work-dir <directory>] [--json]` 使用与现有 CLI 相同的书籍引用和工作区根目录语义；不要求登录态，不读取会话，不访问网络、不创建目录、不修改任何工作区文件。

以有效且书籍 ID 匹配的 Manifest v1 和可解析的 `raw/catalogue.html` 确定预期章节与卷归属。Manifest 中 `catalogue` 记录须为完成状态并含有效 HTTP/HTTPS `sourceUrl`，用该地址解析目录相对链接；缺失或无效时按 `CATALOGUE_INVALID` 处理，不联网补齐。只读取目录引用且 Manifest 标为完成的 `chapters/*.json`，不扫描并吸收孤立缓存。章节 JSON 的 `id`、`sourceUrl` 必须与目录相符，且块结构有效。章节缓存原文不是本命令的必要输入；`book.json` 也不是必要输入，且其中章节不能替代源章节。资源首先按 Manifest 记录定位，`book.json` 仅可辅助定位目录已有图片 URL 对应的文件；文件路径必须位于工作区内。

| 情况                                                                   | 报告状态   | 退出码与行为                                    |
| ---------------------------------------------------------------------- | ---------- | ----------------------------------------------- |
| 必要输入和资源均可检查，没有已检测到的 URL 碎片                        | `complete` | `0`；允许标记数为零，也允许有尚未映射的符号标记 |
| 工作区、Manifest 或目录缺失、损坏，书籍不符，或目录中的章节 URL 不唯一 | `error`    | `1`；`chapters`、`markers`、`images` 数组均为空 |
| 个别章节未完成、缺失、不可读、损坏或身份不符                           | `partial`  | `2`；保留其他有效章节的检查结果，逐章列出缺项   |
| 有地址图片文件缺失、不可读、不可解码，或已有无地址图片块               | `partial`  | `2`；保留候选及不可用原因，不提供可执行来源摘要 |
| 检测到旧 URL 碎片                                                      | `partial`  | `2`；保留可检查结果，报告恢复限制，不推断原 URL |

`complete` 只表示上述检查完整，不证明原书排版已恢复，也不证明不存在未支持的标记。多个问题同时发生时 `error` 优先于 `partial`。没有标记与没有检查到章节必须能从状态及章节计数区分。部分报告中的有效坐标仍可供人工核验；映射能否执行另由完整映射校验决定。

### JSON 报告 v1

对语法有效的 `--json` 调用，上述三种状态均向 stdout 输出且只输出一个 JSON 对象；诊断不能夹杂为 stdout 文本。未带 `--json` 时显示同等状态、计数和问题摘要，退出码相同。不规定人类可读提示的精确措辞。

顶层必填字段如下，计数除特别列出的 `null` 外均为非负整数；所有摘要为 64 位小写十六进制 SHA-256。数组按目录卷章顺序及块下标排列，同一位置的问题按原因码排序；没有章节坐标的诊断置于最前，按原因码排序。

| 字段                          | 契约                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`、`bookId`、`status` | 分别为 `1`、请求的书籍 ID、`complete` / `partial` / `error`                                                                                                                                                                                                                                                                                                     |
| `counts`                      | `{ chaptersExpected, chaptersInspected, symbolMarkers, urlMarkers, imageCandidates, availableImages, legacyUrlFragments }`；预期章节数在无法取得可信目录时为 `null`，其他字段为整数；计数只统计有效源章节及其原始块                                                                                                                                             |
| `chapters`                    | 有效章节数组，每项含 `volumeIndex`、`volumeTitle`、`chapterUrl`、`chapterTitle`、`chapterSha256`；索引从零开始                                                                                                                                                                                                                                                  |
| `markers`                     | 每项含 `kind: "symbol" / "url"`、`chapterUrl`、`chapterSha256`、`blockIndex`、`marker`；URL 标记另含完整 `sourceUrl`。这里仅输出受支持的完整标签，不输出普通正文或 URL 碎片                                                                                                                                                                                     |
| `images`                      | 源 `ImageBlock` 的每个出现位置各一项，含 `chapterUrl`、`chapterSha256`、`blockIndex`、`sourceUrl: string / null`、`availability: "available" / "unavailable"`、`relativePath: string / null`、`assetSha256: string / null`。未实际读取并通过图片校验时摘要为 `null`；路径相对书籍工作区且使用 `/` 分隔。资源复用不合并位置；新恢复的 URL 标记不冒充原始图片候选 |
| `diagnostics`                 | 每项含 `code`，可定位时另含 `chapterUrl`、`blockIndex`；不含正文或原始异常转储。资源问题定位到对应图片块                                                                                                                                                                                                                                                        |

v1 原因码固定为 `WORKSPACE_MISSING`、`MANIFEST_INVALID`、`CATALOGUE_INVALID`、`BOOK_ID_MISMATCH`、`CHAPTER_URL_AMBIGUOUS`、`CHAPTER_INCOMPLETE`、`CHAPTER_MISSING`、`CHAPTER_INVALID`、`IMAGE_SOURCE_MISSING`、`IMAGE_FILE_MISSING`、`IMAGE_FILE_INVALID`、`LEGACY_URL_FRAGMENT`。Manifest、目录缺失也分别使用对应的 `*_INVALID`；不可读章节使用 `CHAPTER_INVALID`，不可读或越界图片路径使用 `IMAGE_FILE_INVALID`。不以图片是否存在映射作为报告完整性的条件。JSON 只枚举这些字段；版本化结构与退出码属于验收接口。

章节摘要、坐标和图片文件摘要与 [设计中的映射契约](design.md#本地映射契约) 使用同一算法。图片摘要必须从本地实际字节计算，不能复制 Manifest 或 `book.json` 的历史值。图片记录为 `available` 才能直接提供映射来源所需的文件摘要。

## 验收条件

1. 未启用新能力时，下载、缓存复用、图片完整性校验和 EPUB 输出行为保持现状。
2. 启用后，按上述语法将完整段落 URL 标记转换为现有 `ImageBlock`，保留完整 URL 和所在位置；覆盖查询参数、片段、转义、标签大小写及各支持扩展名。普通链接、叙述中的引用及不支持的格式保持原文。
3. 按符号标记表逐项验证接受与拒绝示例；识别结果保留原标签和章节身份，覆盖前后空白、前导零、相同标签多次出现、非段落块，不按编号或出现顺序自动分配图片。
4. 离线检查按报告契约输出坐标及摘要；无会话时也能执行，不访问网络或改写工作区。验证完整、部分及错误状态、退出码、JSON 字段、原因码、目录计数和排序，区分零标记与未检查章节；覆盖各类缺缓存、损坏、身份不符和图片不可用场景。
5. 有效映射在目标处替换标记，只移除明确选中的来源图片块；未选中的图片和文字保持顺序，必要时更新空图片章的导航。相同资源继续复用同一文件。
6. 覆盖同卷不同章节编号重置、一个来源图片对应多个显式目标、重复目标、跨卷映射、来源不存在、源章节变动和图片文件变动。冲突或失效映射不能部分应用，也不能通过缺图放宽选项跳过。
7. 仅有编号且没有有效映射时，保留文字标记及原图位置，并汇总未解析情况；已有无地址图片占位和实际图片下载失败继续遵循原有完整性检查。
8. 同一源缓存和同一映射重复生成得到相同的内容排列；关闭重定位后可从源缓存重新生成原排列。旧缓存无需批量迁移；完整标记可恢复，旧下载包的拆散标记只报告限制且各块原样保留。用带查询参数的合成标记经现有 `parsePackedChapter` 产生缓存，验证不拼接、不丢失现存块、不伪报恢复成功；原文不存在时行为相同。
9. 用合成页面和书稿验证行为，不提交真实小说内容或凭证。实施后运行 `pnpm check`，验证 EPUB 引用、导航及 EPUBCheck，并更新架构中实际改变的边界。
