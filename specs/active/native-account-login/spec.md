# 原生账号登录

本文描述待实现的行为，不代表当前功能。产品范围已根据本次对话确定；站点协议与浏览器交接仍需取得下文要求的可行性证据，不能据此宣称技术方案已经验证。

## 目标与已确定的选择

将 `wenku8 login` 从保存用户粘贴的 Cookie 改为站点账号登录入口。用户在终端输入账号、密码；需要验证码或 Cloudflare 验证时，由程序自动打开浏览器，用户完成交互后，程序自动接收并保存可用登录态。整个受支持流程不要求用户查看、复制、导出或粘贴 Cookie。

用户已确定：

- 默认使用终端账号密码登录；浏览器用于需要人工验证的流程。
- 验证完成后自动取得登录态，不以“请复制 Cookie”作为备用流程。
- 移除手动 Cookie 入口，只支持账号登录；这是有意的 CLI 兼容性变更。

## 当前实现与影响边界

- `src/cli.ts` 的 `login` 当前只接收 Cookie 并调用 `saveUserCookie()`，没有账号认证。
- `src/cli/cookie.ts` 当前按参数、环境变量、指定文件、当前目录文件、用户配置文件的顺序解析 Cookie。
- CLI 的联网命令通过 `createClient()` 强制要求 Cookie；其下载请求当前优先使用 curl。
- `src/http/client.ts` 当前提供带 Cookie 的 GET 请求、限速、重试及传输切换，没有完整的账号登录、浏览器验证和跨进程会话保存能力。
- 后续实现需要同步 CLI 帮助、README、认证相关错误、测试以及描述已实现行为的架构文档。本规格阶段不将目标写成已实现事实。

## 预期行为

### 1. 终端账号登录

1. 在有交互终端时执行 `wenku8 login`，提示输入站点账号与密码，密码输入不回显明文。
2. 向站点真实登录流程提交认证信息，正确处理该流程要求的页面编码、表单状态、重定向与会话更新。具体字段和端点以核实结果为准，不预设某个框架的协议。
3. 缺少必需输入时，不提交无效认证请求。用户可取消操作。
4. 仅在确认账号已登录，并验证所得会话可由 CLI 的实际请求流程使用后，才持久化新登录态并输出成功。
5. 密码错误、账号受限、网络失败和需要人工验证应有可区分的提示。HTTP 200、发生跳转或存在某个 Cookie，都不足以单独判定成功。
6. 不自动反复提交失败的账号密码。沿用站点请求限速及 429 冷却边界，不把登录 POST 当作普通 GET 任意重试。

### 2. 浏览器验证与自动交接

1. 登录过程需要验证码或 Cloudflare 等人工验证时，自动打开可见浏览器，说明等待用户完成站点要求的交互。
2. 用户可以在浏览器中完成验证，以及站点为完成登录所要求的后续步骤；程序自动检测完成情况并接收本次流程的登录态。
3. 交接后，使用实际 CLI 传输验证认证访问。浏览器显示登录成功但 CLI 请求仍被拦截时，不报告整体成功，也不保存为已验证的新会话。
4. 无法启动浏览器、缺少必要运行组件、用户关闭浏览器、等待超时或交接失败时，说明原因及可执行的恢复动作，以失败结束，不转为手动 Cookie 导入。
5. 等待过程可取消且有有限的等待上限，取消、超时和失败均清理本次临时资源。具体上限由实现明确并在相关使用说明中记录。
6. 只操作本工具启动或明确管理的登录浏览器会话，不扫描用户日常浏览器的 Cookie 数据库，不依赖用户启用日常浏览器的远程调试。
7. 浏览器中的验证由用户正常完成，不实现验证码代答、伪造验证结果或防护绕过。

### 3. 登录态保存与后续使用

1. 登录成功后，后续进程的搜索、榜单、轻小说大赏、详情、下载和恢复命令自动复用保存的登录态，无需再次输入账号密码或提供 Cookie。
2. 账号密码仅用于本次认证，不作为自动重登凭证持久化。会话属于内部实现，可使用 Cookie，但用户无需管理其值。
3. 新登录失败、取消、超时或写入失败，不破坏原有已保存的会话；写入失败不得输出登录成功。
4. 未登录时，联网命令指向 `wenku8 login`；明确识别到会话失效时，提示重新登录，不将登录页解析为小说内容或正常空搜索结果。
5. 普通 403、网络失败及 Cloudflare 验证失败，不一律解释为账号密码错误或会话已失效。
6. 下载期间遇到会话失效或验证阻断，应明确失败并保留既有可恢复工作区；用户重新执行 `login` 后可按现有恢复方式继续。此次不扩展为下载中自动弹出浏览器或后台自动登录。
7. `wenku8 logout` 清除本工具保存的认证状态，包括实现若引入的可复用浏览器认证资料；不影响下载工作区、EPUB 或用户日常浏览器资料。不承诺注销站点上的其他会话。

### 4. 手动 Cookie 入口移除

1. `login` 及其他 CLI 命令不再接受 `--cookie`、`--cookie-file`，传入时明确报不支持的选项并提示使用账号登录。
2. 不再读取 `WENKU8_COOKIE`、当前目录 `.wenku8-cookie` 或任意用户指定的 Cookie 导入文件，也不提供另一个等价的手动导入入口。
3. 原用户配置目录的 Cookie 文件不作为本次新认证成功的证据；无新登录态的升级用户执行一次账号登录。无需继续依赖或主动删除用户自行创建的旧 Cookie 文件。
4. `config`、命令帮助、缺少凭证和验证失败提示均改为面向账号登录及程序管理的会话，不再引导用户获取 Cookie。
5. 新会话继续归属现有的用户配置目录体系；无需修改默认 EPUB 与工作区目录。具体内部会话格式和文件名由实现确定。
6. 此次移除范围为用户侧 CLI 手动导入能力；不据此要求删除 HTTP 层内部的 Cookie 处理，或变更库导出接口。

## 凭证与传输约束

- 账号密码、Cookie 及其他认证秘密不得进入普通输出、错误、HTTP 统计、进程命令行、测试 fixture、源码或公开日志。用户名可按需要作为身份提示，但密码必须隐藏。
- 密码通过受信任的 HTTPS 站点认证流程提交，不在 HTTP 降级或跨越未核实目标的重定向中发送。
- 保存的会话使用操作系统支持的用户级访问权限；临时浏览器资料按敏感凭证处理，不遗留仓库内资料或日志。
- 会话发送应遵循适用域、路径及安全属性；不能将登录 Cookie 无差别发送到章节、图片或重定向涉及的任意主机。
- 无交互终端或无图形浏览器的环境在无法完成所需交互时，明确退出，不挂起等待，也不读取旧手动 Cookie 来源。本次不增加账号密码参数、环境变量或无人值守登录协议。

## 非目标

- 注册、找回密码、多账号切换、凭证保险库与记住密码。
- 自动解决站点的人机验证，或保证任意网络环境都能通过站点防护。
- 更改 EPUB 构建、图片完整性、Manifest 格式及断点恢复规则。
- 保证旧版 Cookie 脚本继续工作。

## 验收条件

| 场景 | 应观察到的结果 |
| --- | --- |
| 无历史会话，账号密码正确且无需验证 | 终端完成登录；后续新进程的联网命令直接使用所得会话 |
| 账号或密码错误，包括站点用 HTTP 200 返回失败页 | 明确失败，不报告成功，不写入新会话，不自动反复尝试 |
| 需要人工验证 | 自动打开浏览器；用户完成交互后自动交接，CLI 验证可用后保存；全程无需操作 Cookie |
| 浏览器中已登录，交接后的 CLI 请求仍遇到验证 | 明确说明交接未成功，不保存为可用新会话 |
| 浏览器不可用、用户关闭、取消或等待超时 | 有明确结果，清理本次临时资源，原有会话不被破坏 |
| 认证成功但持久化失败 | 报告保存失败，原有会话仍可读取，不报告整体成功 |
| 无会话或会话明确失效 | 引导执行 `wenku8 login`，不提示复制 Cookie，不将登录页当正常业务结果 |
| 下载过程中认证失效 | 明确停止，保留已有进度；再次登录后能继续恢复 |
| 存在旧环境变量、目录 Cookie 或旧用户 Cookie 文件 | 不以其替代账号登录；仅有旧凭证时仍需要执行新登录 |
| 传入旧 Cookie 参数 | 命令报错并提供新入口，不使用该值发请求 |
| 登录请求重定向到未核实目标，或资源请求指向其他主机 | 不泄露密码或超出适用范围的会话 |
| 执行 logout 后启动新进程 | 不再复用本工具的认证状态；下载产物与工作区仍保留 |
| 检查终端输出、错误与测试样例 | 没有密码、Cookie 或其他可复用认证秘密 |

## 验证与实施前调查

产品选择已确定，以下技术问题仍未核实，不作为既有事实或已选技术方案：

1. 站点当前登录表单、编码、必需字段、令牌、验证码类型，以及成功、失败和会话失效的可靠判据。
2. 可自动交接的浏览器集成方式与所需依赖，及其在 Windows、macOS、Linux 上的运行、安装和清理方式。不能只承诺打开默认浏览器，却没有自动接收会话的机制。
3. 验证后的会话是否受浏览器环境、User-Agent 或网络出口等条件约束，以及如何由实际 CLI 传输继续使用。若不能满足自动交接，不得静默降低为粘贴 Cookie，应更新本规格并说明未满足条件。
4. 持久化所需的会话信息与生命周期，包括是否需要浏览器资料、后续响应中的会话更新，以及 logout 的完整清理范围。

本次调查通过只读访问 `https://www.wenku8.net/login.php` 得到 HTTP 403，未取得登录表单；该结果不足以确认是 Cloudflare、站点本身限制还是访问环境所致，也未验证账号认证或会话交接。

实现时以离线脱敏页面、可控 HTTP 服务和浏览器集成测试覆盖表中成功与失败路径，保留已有业务回归。账号密码与真实会话不进入测试样例，CI 不依赖真实站点账号。另需在可访问站点的环境中取得一次真实账号登录和浏览器验证交接的运行证据；无法取得时如实记录未验证项，不能以模拟测试代替真实可行性结论。
